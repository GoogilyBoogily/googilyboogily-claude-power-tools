# X11 / Xorg Troubleshooting

For Wayland sessions see `wayland.md`. Many users on "X11" actually run XWayland — confirm with `echo $XDG_SESSION_TYPE`.

## Quick Triage

```bash
echo "session=$XDG_SESSION_TYPE display=$DISPLAY"
xdpyinfo | grep -E "name of display|version|dimensions|depth"
xrandr --verbose | head -40
xprop -root | grep -i compositor
ls -la /var/log/Xorg.0.log ~/.local/share/xorg/Xorg.0.log 2>/dev/null
grep -E "\(EE\)|\(WW\)" /var/log/Xorg.0.log ~/.local/share/xorg/Xorg.0.log 2>/dev/null
cat ~/.xsession-errors 2>/dev/null
```

`(EE)` lines are errors; `(WW)` are warnings. Recent log location depends on whether Xorg runs as root (legacy `/var/log/Xorg.0.log`) or rootless (`~/.local/share/xorg/Xorg.0.log`).

## Login Loop

User enters password, returns to display manager. Symptoms in `~/.xsession-errors`:

```bash
cat ~/.xsession-errors                              # most recent attempt
journalctl -u display-manager -b --no-pager | tail -80
```

Common causes:

| Cause | Diagnostic | Fix |
|------|-----------|-----|
| `~/.Xauthority` corrupt or root-owned | `ls -la ~/.Xauthority` | `rm ~/.Xauthority` then login |
| Home dir disk full | `df -h ~` | Free space |
| Home dir wrong perms (e.g. 777 from rsync) | `stat -c '%a' ~` should be 700 or 750 | `chmod 750 ~` |
| `~/.profile` or `~/.bash_profile` syntax error | run `bash -n ~/.bash_profile` | Fix or rename |
| Broken systemd user unit | `systemctl --user --failed` | Disable failing unit |
| GPU driver loaded but Xorg can't init | `(EE)` lines in Xorg log | See GPU reference |
| SELinux denying session | `ausearch -m avc -ts recent` | `setroubleshoot` advice |

## Black Screen After GDM/SDDM/LightDM Login

```bash
# Switch to TTY (Ctrl+Alt+F2 or F3)
journalctl -b _COMM=Xorg
journalctl -b -u display-manager
journalctl -b --user -u gnome-session-x11 2>/dev/null
```

If a TTY works, the kernel and GPU are fine — issue is session/compositor startup. If TTY also blank, issue is kernel/KMS — check `dmesg | grep drm`.

## Screen Tearing (X11 without compositor)

| GPU | Fix |
|-----|-----|
| Intel | `/etc/X11/xorg.conf.d/20-intel.conf`: `Option "TearFree" "true"` |
| AMD modesetting | same conf path: `Option "TearFree" "true"` |
| Nvidia | `Option "ForceFullCompositionPipeline" "on"` (Screen section) |
| Any | Run a compositor: KWin/Mutter (full DEs), Picom for tiling WMs (`vsync = true`) |

Picom example minimal config (`~/.config/picom.conf`):

```
backend = "glx";
vsync = true;
use-damage = true;
```

## Cursor / Input Issues

Cursor freezes:

```bash
journalctl -b | grep -iE 'gpu|hang|reset|libinput'
xinput list
```

Causes:
- GPU hang — see GPU reference. Nvidia-specific: try `NVreg_EnableGpuFirmware=0` as workaround.
- libinput device removed and not re-added: `sudo udevadm trigger --action=add`
- xf86-input-evdev dragging instead of libinput: ensure `xf86-input-libinput` is the only input driver installed (`xset -q | grep -i pointer`)

Input lag in games: turn off compositor for fullscreen, or use `vblank_mode=0` for non-vsync GL apps.

## xrandr / Multi-monitor

```bash
xrandr                                              # list outputs
xrandr --output HDMI-1 --mode 2560x1440 --rate 144 --right-of DP-1
xrandr --output HDMI-1 --primary
```

Monitor not detected:
```bash
xrandr --query | grep " connected\| disconnected"
sudo cat /sys/class/drm/card*-*/status              # disconnected/connected at kernel level
```

If kernel says "disconnected" but cable is plugged: cable, port, or display-side power. If kernel says "connected" but Xorg doesn't show it, it's an Xorg config issue — check `/etc/X11/xorg.conf.d/`.

EDID issues (monitor reports wrong modes): force EDID via kernel parameter `drm_kms_helper.edid_firmware=HDMI-A-1:edid/edid.bin` — only if you have a known-good EDID dump.

## Custom Modeline (rare)

```bash
# generate
cvt 1920 1080 75
# example output: Modeline "1920x1080_75.00"  220.50  1920 2056 2256 2592  1080 1083 1088 1135 -hsync +vsync
xrandr --newmode "1920x1080_75.00" 220.50 ...
xrandr --addmode HDMI-1 1920x1080_75.00
xrandr --output HDMI-1 --mode 1920x1080_75.00
```

If the output goes black, the monitor doesn't support that timing. Switch back via `xrandr --auto`.

## xorg.conf Pitfalls

Order of precedence:
1. `/etc/X11/xorg.conf` (legacy, monolithic, avoid)
2. `/etc/X11/xorg.conf.d/*.conf` (preferred, snippet-based)
3. `/usr/share/X11/xorg.conf.d/*.conf` (distro defaults)

Common mistakes:
- Wrong `BusID` in multi-GPU. Find correct: `lspci | grep VGA` outputs `01:00.0` → conf needs `PCI:1:0:0` (decimal).
- `Driver "fglrx"` or other dead driver names → silently fails.
- Syntax error → entire X startup fails. Always check `(EE)` in Xorg log.

Test config without committing:

```bash
sudo Xorg :2 -config /tmp/test.conf -logfile /tmp/test-xorg.log
```

## Display Managers

| DM | Config | Logs |
|----|--------|------|
| GDM | `/etc/gdm/custom.conf` | `journalctl -u gdm` |
| SDDM | `/etc/sddm.conf` + `/etc/sddm.conf.d/` | `journalctl -u sddm` |
| LightDM | `/etc/lightdm/lightdm.conf` | `/var/log/lightdm/` |
| Ly (TTY-based) | `/etc/ly/config.ini` | `journalctl -u ly` |

Toggle Wayland default:
- GDM: `WaylandEnable=true|false` in `[daemon]` section.
- SDDM: `[General] DisplayServer=wayland|x11` in conf.d snippet.
- LightDM: rarely Wayland-capable; use SDDM/GDM instead.

## When to Cross-Reference

- GPU driver loaded but X dies: `nvidia.md` / `mesa.md`
- Xorg starts but desktop apps can't show: `wayland.md` (XWayland section if in Wayland session) or check DBus
- `~/.xsession-errors` mentions DBus or systemd: `boot-systemd.md`
- Hostname-related X auth errors: check `/etc/hosts` for `127.0.0.1 <hostname>` line
